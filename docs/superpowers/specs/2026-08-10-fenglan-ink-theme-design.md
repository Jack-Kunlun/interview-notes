# 风岚水墨风视觉主题重构设计

## 背景

「风岚 · 前端面试笔记」是基于 VitePress 1.6 的前端知识库。项目未使用 Tailwind，主题入口为 `docs/.vitepress/theme/style.css`，通过 VitePress CSS Variables 与 `.dark` 变量覆盖实现明暗主题。

当前工作区已有第一版水墨主题草稿，包括配色、首页 SVG 图标和部分公共组件样式。该草稿作为本次重构起点继续完善，不回退或重建项目。

## 目标

将网站收敛为「现代山岚型」视觉：第一眼是克制、清晰的现代技术知识库，第二眼才感受到山岚、宣纸和水墨留白。

本次仅调整视觉表现，不改变：

- 信息架构、导航结构和现有路由；
- 页面文案和文章内容；
- 业务逻辑与搜索功能；
- VitePress 组件层级和页面 DOM 结构；
- 现有响应式布局的基本行为。

## 设计方向

采用已确认的方案 B「现代山岚型」：

- 现代技术感约 65%，东方水墨气质约 35%；
- 以宣纸白、雾灰和墨色为主体；
- 岚青只用于品牌、交互和少量强调；
- 水墨装饰保持 3%–8% 的低透明度；
- 不使用照片、卷轴、印章、中国红、金色边框或大面积古风字体。

## 样式架构

继续使用现有 VitePress 默认主题和单一主题样式入口，不增加业务组件或新的运行时主题逻辑。

`style.css` 按以下职责组织：

1. Light 语义 Token；
2. 全局背景、字体和基础交互；
3. 首页 Hero、操作按钮与知识卡片；
4. 导航、搜索、下拉菜单和移动端菜单；
5. 侧边栏、右侧目录与分页；
6. 文章纸面、正文排版、代码块、表格和提示容器；
7. Dark Token 覆盖与少量必要的暗色组件修正；
8. 响应式及减少动画偏好。

组件样式引用语义 Token，不在大量选择器中重复硬编码颜色。Light 与 Dark 共用相同 Token 名称，只替换变量值。

## Design Tokens

### 语义层级

建立并复用以下语义类别：

- `surface-page`：整页背景；
- `surface-subtle`：侧栏和次级区域；
- `surface-paper`：文章与卡片纸面；
- `surface-elevated`：搜索、下拉和浮层；
- `text-primary`、`text-secondary`、`text-muted`；
- `border-subtle`、`border-interactive`；
- `brand`、`brand-hover`、`brand-soft`；
- `accent-tea`：仅用于 warning 等少量语义强调；
- `shadow-soft`、`shadow-hover`；
- `focus-ring`。

这些语义 Token 映射到 VitePress 的 `--vp-*` 变量以及少量 `--fenglan-*` 自定义变量，使默认组件与定制样式保持一致。

### Light

- 页面背景：`#F7F7F2`；
- 次级背景：`#F1F2ED`；
- 文章与卡片纸面：接近 `rgba(255, 255, 255, 0.72)`；
- 主文字：`#202522`；
- 标题：`#17231D`；
- 次级文字：`#5F6963`；
- 弱化文字：`#8B938E`；
- 品牌色：`#2F6F59`；
- Hover：`#275D4B`；
- 少量茶褐强调：`#9B7B4F`。

### Dark

- 页面背景：`#111714`；
- 次级区域：`#151C18`；
- 文章与卡片纸面：`#18201C` 附近；
- 主文字：`#E8ECE9`；
- 次级文字：`#9BA69F`；
- 品牌色：`#62A98A`；
- 边框：低透明度雾青。

暗色页面不使用纯黑，也不使用大面积高饱和深绿。文章纸面只比页面背景略亮，通过边框和微弱阴影建立层级。

## 页面表面与背景

页面底层使用宣纸白与极淡雾灰。正文区域不再使用当前偏灰绿的大色块，而是表现为宣纸背景上的轻薄纸面：接近白色、低对比边框、极淡阴影。

首页 Hero 右侧通过 CSS 渐变和模糊形成若隐若现的远山与雾气，不引入山水图片。所有水墨装饰透明度不超过 8%，并避开主要文字区域。

暗色主题保留同样的山岚结构，但进一步降低透明度。

## 公共组件

### 导航与品牌

- 导航使用半透明宣纸背景与轻微 `backdrop-filter`；
- 底部保留 `1px` 极淡分隔线，不使用明显阴影；
- 激活项使用岚青文字和短下划线，不使用大色块；
- Logo 左侧通过 CSS 或 SVG 增加极简山岚线，不使用 emoji；
- 不改变导航项、下拉层级或链接。

### 首页 Hero

- 保留现有标题、副标题、技术描述和三个操作按钮；
- 主标题使用墨色到岚青的克制渐变；
- 保留小号 `FRONTEND NOTES` 辅助文字；
- 增加留白并减弱营销 Banner 感；
- 分隔符使用弱化墨绿，不改变原文含义。

### 按钮

- 主按钮为实心岚青，白色文字和轻阴影；
- 次按钮为透明 Ghost 样式；
- Hover 只改变表面、边框和少量位移；
- 键盘焦点提供清晰可见的 `focus-ring`。

### 知识卡片与图标

- 卡片使用半透明浅纸面、细边框和极淡阴影；
- Hover 使用边框增强、阴影增强及 `-0.25rem` 位移；
- 统一 SVG 图标尺寸、线宽、容器背景和圆角；
- SVG 使用 `currentColor`，保证 Light/Dark 自动适配；
- 不使用 emoji 或不同的高饱和图标色。

### 搜索与浮层

搜索按钮、搜索弹窗、导航下拉、移动端菜单和浮层统一使用 `surface-elevated`、`border-subtle` 与同一组阴影 Token。交互态使用品牌色和清晰的焦点反馈。

### 侧边栏与目录

侧边栏保持原有层级和折叠逻辑。分组标题、普通链接、激活链接和右侧目录按三级文字颜色区分。激活状态使用细线或弱背景，不使用大面积绿色。

### 正文与技术内容

- 标题保持现代无衬线字体，建立稳定的字号、字重和间距层级；
- 正文保持足够对比度与行高；
- 链接使用岚青和克制下划线；
- 行内代码、代码块、表格、引用、提示容器和分页统一使用 Token；
- 茶褐色只用于 warning 等少量语义状态；
- 文章页、面试题页、准备页和贡献页共享同一正文体系。

## 字体与数值约束

- 正文使用 `PingFang SC`、`Microsoft YaHei`、系统无衬线和 `Inter` 回退；
- Logo 可少量使用现代宋体作为品牌回退，但正文不使用古风字体；
- 间距、尺寸、圆角和位移优先使用 `rem`；
- 使用像素单位时，除 `1px` 细边框外，只使用偶数像素值；
- 不使用 `3px`、`5px` 等其他奇数像素值；
- 卡片 Hover 位移使用 `-0.25rem`，不使用 `-3px`。

## 动效与可访问性

- 常规过渡约 200–240ms，保持轻量；
- 卡片与按钮只使用小幅位移、边框和阴影变化；
- `prefers-reduced-motion: reduce` 下移除非必要动画和位移；
- 保留明显的键盘焦点状态；
- 正文、链接、按钮与弱化文字满足可读性和合理对比度。

## 响应式行为

不改变 VitePress 现有断点和组件层级，只在现有断点内修正尺寸、间距和溢出：

- 桌面导航和多列首页卡片保持现有结构；
- 移动端导航、搜索和侧栏保持现有触发逻辑；
- Hero 字号与留白在小屏下收敛；
- 表格、代码块和长文本不得造成页面横向溢出；
- 触控目标维持足够尺寸。

## 实施边界

允许修改：

- `docs/.vitepress/theme/style.css`；
- `docs/.vitepress/config.mts` 中与视觉元信息直接相关的值；
- `docs/index.md` 中现有图标引用与不改变文案含义的展示标记；
- `docs/public/icons/` 中的统一线性 SVG 图标。

不新增 Vue 业务组件，不修改 Markdown 正文内容，不重排导航，不改变链接和路由。

## 验收与验证

### 静态检查

- 搜索旧主题色和旧绿色硬编码；
- 搜索组件选择器内重复的颜色字面量；
- 检查 SVG 是否统一使用 `currentColor`；
- 检查除 `1px` 细边框外是否存在奇数像素值；
- 确认所有视觉值来自统一 Token 或明确的语义状态。

### 构建检查

- 执行 VitePress 生产构建；
- 确认没有失效资源、构建错误或新增警告；
- 检查浏览器控制台错误。

### 视觉检查

在 Light/Dark 下检查：

- 首页；
- 普通文章页；
- 面试题页；
- 贡献页；
- 导航下拉、搜索弹窗和移动端菜单；
- 侧栏、右侧目录、分页；
- 代码块、表格、引用和提示容器。

覆盖常见桌面宽度和移动端断点，验证文字对比度、布局溢出、交互态、焦点态与减少动画偏好。

## 成功标准

完成后的页面应满足：

1. 第一眼是高级、安静且现代的技术知识库；
2. 第二眼才显现山岚、宣纸与水墨留白；
3. 页面不再被大面积绿色或灰绿色表面主导；
4. 首页与所有文档类页面使用同一套视觉语言；
5. Light/Dark、桌面/移动端均保持清晰可读；
6. 现有功能、路由、导航、文案和组件层级不变。
