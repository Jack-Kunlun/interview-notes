# 行为面试题（STAR 法则）

> STAR = **S**ituation（背景）/ **T**ask（任务）/ **A**ction（行动）/ **R**esult（结果）

---

## Q1：描述一次你独立负责并推动完成的复杂项目

**参考框架**：

- **S**：项目背景（公司/团队规模、技术栈、初始状态）
- **T**：你负责的核心模块或目标（如：独立开发多租户权限系统、主导前端架构重构）
- **A**：具体怎么做（技术选型决策、攻克了什么难点、如何推动跨团队协作）
- **R**：量化结果（如：首屏加载从 4.2s → 1.8s，用户投诉率下降 30%，日活提升 X%）

---

## Q2：讲一个你与团队成员产生技术分歧，最终如何解决的经历

**参考框架**：

- **S**：分歧背景（如：技术选型争议，是选 Vue 还是 React；或是代码 Review 中对某方案的不同意见）
- **T**：你的立场和对方的立场分别是什么
- **A**：如何沟通（数据对比、原型验证、寻求共识、引入更权威的参考）
- **R**：最终决定是什么，对项目产生了什么影响，你从中学到了什么

---

## Q3：描述一次你主动发现并解决了一个潜在技术风险的经历

**参考框架**：

- **S**：当时的项目状态（如：临近上线、团队忙于功能开发）
- **T**：你发现了什么风险（如：内存泄漏、XSS 漏洞、大促期间的性能瓶颈）
- **A**：你如何定位问题（工具/方法）、说服团队停下来处理、以及修复方案
- **R**：规避了什么损失（如：提前发现避免了大促崩溃，保住了 SLA）

---

## Q4：你如何快速上手一个陌生的大型代码库？

**参考框架**：

- **S**：入职新公司或接手存量项目的背景
- **T**：在多短时间内需要能独立交付
- **A**：
  1. **先跑起来**：`README` → 本地环境搭建 → 跑通主要流程
  2. **读架构文档**：找 `docs/` 目录，或通过 `git log --oneline` 看历史演进
  3. **跟着功能走**：挑一个你要修改的模块，从入口往下追调用链
  4. **问 + 记**：向同事确认不清晰的约定，记录到个人 Wiki
- **R**：X 天内独立交付了 X 个需求，没有引入新 Bug
